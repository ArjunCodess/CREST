Verified November 19, 2026. **Make IEEE ITSC 2027 the primary research submission and take the December 1 ITE abstract as the first opportunity.** CREST's strongest next contribution is a traffic estimator that stays useful when sensors go missing, knows when the available readings cannot support a decision, and can show both on held-out measured traffic.

## What to change in CREST

The competition replay reproduced 6,980,503 values within numerical tolerance. The original entry scored 0.83220 on the public leaderboard, and the attributed hybrid scored 0.87387. The stronger engineering signal is the research holdout. Its hard-constrained estimator had 81 valid fits out of 100 scenarios and a missing-storage RMSE of 32.4108 vehicles where both methods could be scored, versus 6.6591 for masked mean. The OD NNLS comparison was withdrawn because missing count rows were treated as zero. The measured pilot used a roughly 66-second I-80 slice. Those findings make observation handling, measured transfer and useful failure responses the priorities. [Replay receipt](../results/checkpoint_replay.json) · [Frozen results](research_results.md) · [Analysis erratum](research_analysis_erratum.md) · [Measured pilot](research_measured.md)

### 1. Give the estimator a reliable observation contract

Extend [the measured path](../src/research/measured_runner.py) with a common input for detector and trajectory data. Each observation needs a source and directed station or cell ID, channel, units, lane scope, event interval, arrival time, quality flag and measurement mask. Keep count, rate, occupancy and storage as distinct channels. Persist input hashes and topology versions. Keep a separate evaluation view for withheld measurements, and load it only after prediction. Split offline smoothing and causal forecasting at the interface so state filled with future readings cannot flow into the queue forecast.

Start archiving authorized copies of the public five-minute PeMS feed for Districts 4 and 7 and snapshot the station metadata. On Nov 19 both feeds returned data, and each directory listed seven timestamped files, so forward collection matters. Use one collector with idempotent writes keyed by district and interval, record gaps explicitly, and archive enough contiguous windows to test detector outages. Probe the actual files against the field specification. Check which channels are reported or imputed, confirm local timestamps and lane mapping, and score only readings of declared quality. Confirm redistribution rights before packaging raw records. [Caltrans PeMS feed](https://pems.dot.ca.gov/) · [District 4 files](https://pems.dot.ca.gov/feeds/D4/Data/5min/) · [District 7 files](https://pems.dot.ca.gov/feeds/D7/Data/5min/)

Extend the trajectory adapter to complete FHWA NGSIM I-80 and US-101 recordings, grouped by site and period. The catalog API reports about 9.37 million rows across the two sites, so size new storage before the fetch and stream by recording or stable time ranges rather than lifting the existing 25,000-row cap in place. NGSIM gives trajectory-derived storage, crossings and queue labels at its own scale. PeMS supports five-minute state and detector-based congestion proxies. Full I-24 is a later option if access, units and terms are verified. [Trajectory adapter](../src/research/trajectory_adapter.py) · [FHWA NGSIM](https://catalog.data.gov/dataset/next-generation-simulation-ngsim-vehicle-trajectories-and-supporting-data) · [Data manifest](../configs/research_data_manifest.json)

**Done when** feeds and recordings produce auditable windows under one contract, the same masked window reaches every model, and a future-reading canary leaves causal outputs unchanged. Ship a small synthetic fixture that exercises duplicate arrivals, missed intervals and unit conversions, plus a manifest of the measured windows and available evidence.

### 2. Replace the hard fit with a sparse estimator that reports limits

Use the original CREST tree model or a simpler train-only baseline as the initial state estimate. Reuse directed wave features only if they add value in held-out comparisons. Refactor [the dense cumulative storage formulation](../src/research/conservation_constraints.py) into sparse, local-in-time balance equations with explicit storage variables, signed boundary incidence and separate internal, inlet, outlet and ramp flows. Start with chain and merge/diverge layouts. For the synthetic testbed, add cell-transmission supply and demand plus junction allocation, and use a second truth generator or measured trajectories to test misspecification. The estimator should not gain an advantage from sharing all its dynamics with the test generator. [Original wave model](../src/wave_v7.py) · [Current simulator](../src/research/synthetic_sim.py)

Build two outputs over the shared equations. The point estimator uses a robust observation loss and a train-calibrated prior to keep a single noisy sensor from forcing large errors across the network. A sparse QP with a Huber loss and explicit observation residuals is a practical first implementation. Keep balance, nonnegative storage/flux and defensible capacities as hard constraints within the chosen model. Where the inputs cannot justify a constraint, carry its uncertainty through a bounded variable or report the missing evidence. The second output uses hard observation/boundary intervals in an LP to return model-conditional bounds for operator-relevant quantities, with explicit infeasible, unbounded and numerical failure statuses. If the LP is empty, report conflicting measurements and any separate soft point estimate as degraded. If a solve times out or its output cannot support a decision, return a flagged baseline or abstain. Report the fallback and its error in the full denominator. [Current point estimator and LP](../src/research/boundary_conservation.py) · [LP status contract](../src/research/lp_core.py)

**Done when** the sparse and existing dense LPs agree on small unchanged fixtures within a declared solver tolerance, the new estimate handles a biased or missing sensor without silently relaxing balance, and the audit shows residuals, interval widths, infeasibility and all fallback outcomes. Size the problem by links, edges and windows and measure runtime and peak memory before replacing the prototype solver.

### 3. Make queue and route outputs depend on the available evidence

Build a causal queue head on rolling reconstructed state and uncertainty, plus directed upstream/downstream history. Use the same features for onset probability, queue-tail location and lead time. Reuse [the event model](../src/queue_events.py) for the first comparator. Remove the competition's fixed onset-window assumption from measured and vehicle-facing evaluation. Lock trajectory-label and detector-proxy definitions on development data, and score them separately. Simulated or sampled probes should carry an explicit delay and penetration mask. Defer a queue warning when location uncertainty or feed age exceeds a development-set threshold.

Fix OD comparators by slicing the incidence matrix and counts with the same observed, finite mask **before** constructing count centers. Repair both the [experiment call site](../src/research/experiments.py) and [the research baseline wrapper](../src/research/baselines.py), then verify the case where omitting a row differs from observing zero. Reuse [CREST's link-space solver](../src/od_v6.py) as a point comparator and [the partial-identification module](../src/research/partial_identification.py) for selected aggregate LP bounds. Test alternate paths and withheld counters on a branching synthetic network. Return wide intervals or unbounded status when the observed rows cannot resolve a requested aggregate. Keep route flows out of measured-accuracy claims until a suitable network has independently observed route truth.

**Done when** causal queues have event-level lead time and false-alarm results, and the same missing counts are passed to every OD method. Test whether adding an independent counter narrows selected conditional bounds. Keep this OD track off the ITSC critical path if route evidence remains synthetic.

### 4. Run a comparison that could disprove the contribution

Build a new protocol on [the existing runner](../src/research/runner.py). Use site-held-out and time-blocked measured splits with a history buffer, and a distinct synthetic split by topology and demand regime. Hold entire recordings or corridor-days together. Give each method the same masks, causal inputs and tuning budget. Compare persistence and a historical profile, an original CREST tree model, a traffic-specific method such as a CTM with an ensemble Kalman filter, and a learned spatiotemporal imputer such as GRIN for the offline state task. Use a causal graph comparator for the queue task if the offline one sees later inputs. Run unconstrained and constrained versions of the same prior so any improvement can be attributed to the constraints.

Predeclare the primary comparison on development data before the final execution. Start with five-minute speed MAE under 30- to 60-minute detector outages on PeMS, compared with the strongest matched method selected on development data. Require the paired 95% cluster interval to support the improvement. Set the flow and normal-condition noninferiority margins before the holdout using detector noise and the intended operational use. If the PeMS cohort falls short, activate a trajectory-based primary outcome defined in the same protocol before seeing any reserve results. Resample independent days, recordings or seed clusters. The initial performance budget is a five-minute end-to-end p95 on CPU for the shadow update, measured alongside peak memory and cold-start latency.

Publish error by channel, units and operating regime, interval coverage and width on observable truth, queue lead time and false alarms, and abstention coverage. Score emitted fallback predictions and report all eligible windows in the failure and abstention denominators. Calibrate empirical prediction intervals on a distinct development/calibration split and publish their coverage separately from the LP's assumption-conditional bounds. If accuracy does not improve, pursue the research claim only if a preregistered alternative shows useful uncertainty or decision quality at matched coverage. [Existing protocol](research_protocol.md) · [Bootstrap and denominator erratum](research_analysis_erratum.md)

Freeze the code, data manifest, calibration split, metric definitions and artifact digests before the new run. Preserve the v3 failure and completed v4 as historical evidence. Use a clean-install CPU fixture to regenerate a small evaluation receipt independently of the competition checkpoints. A release should let a reviewer distinguish measured results, synthetic truth and proxy labels directly in the generated tables.

## What each venue should get

### ITE Annual Meeting — detector outage triage

ITE publishes a subject-matter panel score of 1 to 4 and asks for practical approaches to incident detection, response and transportation operations. Build a timestamped outage replay on one corridor that contrasts a dropped or stale detector with coherent congestion across neighboring detectors. Expose the last good reading, reconstruction, confidence, and whether a reviewer should inspect the detector or corroborate an emerging queue. The minimum by Nov 27 is one logged outage case and one congestion case, with a runnable baseline and a record of when the two are confused. The abstract can present a prototype with injected outages and stress its limitations. Choose the poster if the workflow is useful but still too preliminary to support a practice result. [ITE program and abstract review](https://ite.secure-platform.com/annual-meeting/)

### ACM SIGMOD — incremental replay of traffic estimates

SIGMOD judges both audience experience and the system's intellectual contribution. Build a small data system around a partitioned Parquet event log, immutable run manifests and dependency tracking at the corridor/window level. A reviewer should be able to remove or correct a detector batch, see which windows become stale, and inspect the changed estimates and their inputs. Key cached results on input, topology and estimator versions. Record each estimator's lookback and smoothing window in its dependency graph so late events invalidate every affected output. For state carried across windows, replay from the last unaffected checkpoint. Test that incremental replay matches full recomputation and preserves unaffected outputs under out-of-order arrivals and duplicates. Compare latency and work done, and reproduce the scenario on a clean CPU install. Skip the call if the only working interaction is rendering existing predictions. [SIGMOD demo selection criteria](https://2027.sigmod.org/calls_sigmod_demos.shtml)

### ITS World Congress — a measured shadow pilot

The technical-paper rubric asks for an original improvement to practice, practical trial outcomes and enough data to support conclusions applicable beyond the case. Put detector ingest, estimation and stale-feed handling into a scheduled shadow run with a read-only operator feed and a replayable incident ledger. On independent measured periods, inject contiguous blackouts and delayed measurements, then compare completeness, time to recovery and bad-alert rate against the latest available reading or a historical profile. Measure end-to-end update latency against the five-minute input cadence and include a second corridor or distinct operating period to check portability. A technical paper needs a completed pilot and corroboration beyond a single handpicked incident. A poster can present a smaller measured result with its stage and limitations stated, consistent with the published poster rubric. [Congress themes and tracks](https://www.2027.itsworldcongress.com/programme/theme-topics) · [Technical paper criteria](https://www.2027.itsworldcongress.com/files/Programme/Technical%20Paper%20Review%20Criteria.pdf) · [Poster criteria](https://www.2027.itsworldcongress.com/files/Programme/Poster%20Review%20Criteria.pdf)

### IEEE IV workshop — an infrastructure-to-vehicle queue advisory

The symposium's review guidance stresses technical soundness and an intelligent-vehicle contribution. Use that as a provisional bar until an accepted workshop publishes its own scope and criteria. Build a read-only advisory consumer for a moving probe. The message contains observation time, expiry, direction, a queue-tail location interval, and an explicit unavailable state. Replay instrumented trajectories with simulated probe loss and communication delay. Compare to probe-only speed thresholding and an unfiltered infrastructure warning. Score lead time before queue encounter, false warnings per trip, and the fraction of warnings withheld or expired. Submit only if a workshop explicitly fits cooperative sensing or vehicle-infrastructure traffic dynamics and the advisory has its own evidence. [IV workshop dates and proceedings](https://ieee-iv.org/2027/contributions/call-for-workshop-and-tutorials-proposals/) · [Symposium review guidelines](https://ieee-iv.org/2027/contributions/reviews-guidelines/)

### IEEE ITSC — state recovery and queue inference through sparse outages

ITSC's scope covers traffic analytics, validation and field tests. Its review guidance emphasizes technical soundness, contribution and strong experimental evidence. Deliver the sparse boundary-aware estimator and causal queue head as one testable system. The paper should answer whether explicit boundary uncertainty and junction physics improve recovery or warning decisions when a detector run disappears. Run matched ablations for wave features, soft versus hard observations, and boundary constraints. Test transfer on a held-out measured site, validate balance against independently derived storage and crossings where available, and measure how bad assumptions affect abstention. Advance only when the frozen evaluation supports an accuracy or decision-quality result with useful coverage. [ITSC scope and dates](https://ieee-itsc.org/2027/contributions/call-for-papers/) · [ITSC review guidelines](https://ieee-itsc.org/2027/contributions/reviews-guidelines/)

### ACM KDD Datasets and Benchmarks — an outage and identifiability benchmark

The published 2027 Cycle 1 criteria are accessibility, quality and documentation, impact, and ethics and fairness. Use those until the Cycle 2 call is published. Package fixed topology/time splits, a generator with controlled detector loss and known synthetic truth, a measured evaluation slice with clear permissions, and a scorer that evaluates point error, interval coverage/width, failure rate and abstention at matched coverage. Add fixtures that catch leaked targets, misplaced masks and rankings distorted by dropped failures. Quantify where the generator resembles and misses measured data using outage lengths, speeds/flows and congestion durations. Publish licenses and selection rules by source and disclose geography and time-of-day coverage. The benchmark earns its own submission if an independent clean install can evaluate several credible methods and the stress cases reveal a reproducible failure or ranking change that standard random masking misses. A leaderboard export or a repackaged competition dataset does not meet that bar. [KDD evaluation criteria and scope](https://kdd2027.kdd.org/datasets-and-benchmarks-track-call-for-papers/)

The first concrete deliverable is a replay with source hashes, a fixed detector outage, a congestion window and a scored baseline. That gives ITE a usable result and gives every later branch the same way to inspect what CREST saw and why it responded as it did.
