# CREST

**Constrained Reconstruction and Estimation of Spatiotemporal Traffic**

CREST reconstructs missing freeway measurements, predicts short-horizon queues, and estimates nonnegative path flows from sparse link counts. It combines graph and temporal features, wave-aware residual models, physical feasibility constraints, and explicitly attributed external checkpoints. Numerical replay makes the final predictions inspectable; generalization to real traffic remains untested.

The research implementation by **Arjun Vijay Prakash** covers four connected tasks on the synthetic TrafficFlowBench participant release:

- Recover missing speed and flow across ten directional corridors.
- Predict queue membership at six five-minute horizons.
- Check fundamental-diagram feasibility while distinguishing it from vehicle conservation.
- Estimate path demand against observed link counts and a weak prior.

The manuscript is [paper/working_notes.tex](paper/working_notes.tex), with its compiled PDF at [paper/working_notes.pdf](paper/working_notes.pdf).

## Key achievements

- Purged temporal validation separates fitting and validation feature construction; a separate family-held-out experiment tests shared tree features.
- Directed wave context augments cross-sensor residual trees, with paired development-block comparisons and explicit promotion gates.
- A link-space dual solver estimates nonnegative path flows without a dense path-by-path Hessian; small-case tests compare it against primal nonnegative least squares.
- The final checkpoint replay matched all 6,980,503 submission rows within numerical tolerance, generating predictions before reading the reference CSV.
- External sources, licenses, and blending weights remain explicit, so ensemble performance cannot be mistaken for the original pipeline's result.

## Overview

### What it does

CREST reads road topology, masked observations, queue histories, and path-incidence matrices. Reconstruction uses graph and temporal context; queue heads use causal histories; path estimation fits released counts. The merger rejects missing, nonfinite, duplicated, or invalid predictions instead of silently filling them.

### Why it matters

Sparse traffic measurements couple prediction and physical feasibility, but available observations do not identify every evaluation target. CREST separates measured results, proxy experiments, and unavailable official quantities so the limits of the system remain visible.

### What is contributed here

The original system integrates graph-temporal boosting, cross-sensor residual features, directed wave context, conditional queue localization, a fixed-speed feasibility map, and regularized nonnegative path estimation. The contribution is an evaluated applied system and its experimental controls. Its individual learning and optimization techniques are established methods; this repository does not establish a new general-purpose algorithm.

The final ensemble additionally uses anubisyy's public CatBoost reconstruction and causal queue checkpoints and BizAI's U-Net2 checkpoints. Those models belong to their authors. See [THIRD_PARTY.md](THIRD_PARTY.md).

### How it works

1. Read official schemas and construct directed upstream/downstream features with twelve five-minute history steps.
2. Fit reconstruction models on the training prefix, using a purged temporal boundary and artificial masking for development comparisons.
3. Estimate queue locations from causal histories, conditioning on the published onset-window contract where applicable.
4. Constrain speed and flow against the triangular fundamental diagram. Derived density makes `q = k * v` an identity; it does not prove conservation.
5. Solve regularized nonnegative path flows against finite observed counts and the released prior.
6. Replay selected checkpoints, blend attributed state predictions, and validate the complete ordered upload contract.

### What we found

The original system reached a public composite of **0.83220**. Public queue replacement and state blending yielded **0.86438**; adding BizAI U-Net2 state predictions yielded **0.87387**. These are historical public leaderboard receipts, not scores generated by running this checkout. Private scores and official task-level breakdowns remain unavailable.

The primary state blend is 25% original reconstruction, 25% anubisyy CatBoost, and 50% BizAI U-Net2. The fallback uses equal original/CatBoost weights. Both retain the original path solver and use public queue checkpoints. The original wave update's isolated public gain was 0.00013 composite, substantially smaller than the ensemble gains.

The [preserved replay receipt](results/checkpoint_replay.json) covers 6,735,795 state rows, 174,000 queue rows, and 70,708 path-flow rows. Queue and path values matched exactly; the maximum state difference was 5.46e-12. Different CSV serialization produced different byte hashes, so this is numerical reproducibility rather than a byte-identical file.

## Running

Run commands from this directory. Create an environment and install the recorded replay dependencies:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-v8.lock.txt
python -m pytest
```

On Linux or macOS, activate with `source .venv/bin/activate`. The recorded environment used Python 3.14 and an RTX 4060 with 8 GB VRAM. A compatible CUDA PyTorch build is required for GPU execution. [The reproduction guide](docs/reproducibility.md) separates setup, original training, and final checkpoint replay.

Check restored replay inputs before starting inference:

```powershell
python scripts/validate_v8_prereqs.py --release-root PATH_TO_PUBLIC_RELEASE --package-root PATH_TO_RESTORED_PACKAGE
```

Generate the final hybrid from a restored checkpoint package and the official participant release:

```powershell
python scripts/reproduce_v8_submission.py --release-root PATH_TO_PUBLIC_RELEASE --package-root PATH_TO_RESTORED_PACKAGE --output artifacts/replayed --device GPU
```

Use `--variant cat` for the fallback. Optional `--reference PATH_TO_REFERENCE.csv` compares values after prediction. A source checkout does not contain fitted weights or raw observations; those inputs must be restored. Synthetic fixtures test software behavior and cannot reproduce benchmark scores.

## Interpretation caveats

- Queue labels are withheld, so observed-speed proxies cannot establish official queue accuracy.
- Official conservation depends on unreleased boundary flows. Fundamental-diagram feasibility cannot certify near-zero conservation error.
- Link counts underdetermine path demand; a close count fit does not identify hidden path truth.
- Later development blocks participated in retention decisions, so their improvements are not independent test estimates.
- Neural reconstruction used a short compute-limited fit and underperformed trees; this does not establish general superiority of tree models.
- Synthetic corridors and public leaderboard gains do not establish robustness on measured traffic or an unseen benchmark.
